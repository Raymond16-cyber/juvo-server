# MT5 connector migration and delivery report

## Release status

Implemented in the existing JUVO repositories, not as a separate prototype. This release replaces the external MetaApi route with a first-party read-only MT5 EA. Follow the [installation and acceptance checklist](../connectors/mt5/README.md) before connecting a real account.

1. **Removed files/features.** Removed the former `brokers/metaapi/metaapi.client.js`, `metaapi.config.js`, `metaapi.controller.js`, `metaapi.errors.js`, `metaapi.history.js`, `metaapi.listeners.js`, `metaapi.manager.js`, `metaapi.routes.js`, and `metaapi.service.js`. Migrated the useful mapper/sync logic into `brokers/metatrader`, replacing its SDK field assumptions with MT5 protocol fields. Removed hosted configuration links, resource provisioning/deployment, SDK stream listeners, retry/stream lease fields, cloud lifecycle status controls and old configuration/workflow tests. Replaced the existing client `MetaTraderConnections` component and service methods; removed the MT4 selector, investor-password setup copy and cloud reconnect controls.

2. **Dependencies.** Removed `metaapi.cloud-sdk` and its unused transitive dependencies through npm (202 packages removed). Existing cTrader `ws`, Express, Mongoose and other unrelated dependencies remain.

3. **Environment.** No `METAAPI_TOKEN` or other MetaApi configuration is read or required by the application. The ignored local environment file was not printed or erased. New settings are `MT5_CONNECTOR_URL`, optional development `MT5_DEBUG`, and optional explicitly configured `TRUST_PROXY_HOPS` for trusted TLS termination. Existing JWT/database/cTrader configuration remains. No provider secret is exposed to the browser.

4. **Database migration.** Startup runs an idempotent legacy migration. Old MetaApi BrokerConnections become `provider=metatrader`, disconnected, disabled and marked legacy; their old resource identity is hidden for audit. Linked accounts are marked disconnected. Existing Trade documents change source only, preserving IDs, journals, notes and analytics history. Position snapshots are retired as unknown. No Trade, Journal or account is deleted. `node scripts/migrate-metatrader.js` reports counts without writes; `--apply` applies the same migration. The earlier cTrader index-name compatibility fix remains, comparing index definitions instead of dropping indexes. Startup completed the migration/index stage against the configured development database during verification; the extra server process then exited because the existing backend already occupied port 5000.

5. **Backend files.** New `brokers/metatrader/metatrader.security.js`, `.validation.js`, `.pairing.js`, `.runtime.js`, `.routes.js`, `.mapper.js`, `.sync.js`, `.migration.js`, and `.initialize.js`. Added `models/ConnectorPairing.js`, `ConnectorHistorySync.js`, and the broker ingestion ledger `BrokerHistoryEvent.model.js`. Integrated with existing BrokerConnection, BrokerPosition, TradingAccount, Trade, shared broker routes/services and the authenticated realtime hub. No extra WebSocket server was introduced.

6. **EA location.** `server/connectors/mt5/JUVOConnector.mq5`, plus its README. MetaEditor outputs are ignored by git; the downloadable source is the maintained artifact.

7. **Pairing.** A signed-in JUVO user requests a random, ten-minute pairing code. Only its hash is stored. The terminal submits protocol version, connector version, code, persistent attempt ID and account snapshot. Atomic consumption binds it to one user/account/attempt. Identical retry can recover a lost response within expiry; another attempt/account cannot consume it again. New pairing rotates the account credential.

8. **Connector token.** An opaque `jmt_` credential derived using HMAC with a separate namespace, not the user's browser JWT. MongoDB stores its SHA-256 hash. It authorizes only connector uploads for the bound owner and MT5 server/login identity. Revoked tokens, deleted users and mismatched account keys are rejected. Browser endpoints do not return it.

9. **API endpoints.** Under `/api/broker/metatrader` (also the existing `/api/brokers` alias): public `GET /download`; browser-authenticated `GET /status`, `POST /pairing-code`, `POST /connections/:id/sync`, `POST /connections/:id/disconnect`; rate-limited `POST /pair`; connector-authenticated `POST /heartbeat`, `/account`, `/positions`, `/history`, `/revoke`. All uploads use JSON protocol version 1. `Accept: text/plain` selects a fixed seven-line acknowledgement for the EA: JUVO1, token-or-empty, connection-ID-or-empty, account-key-or-empty, history cursor, requested-sync timestamp, reconciliation flag. Browser responses use JSON. There are no execution endpoints.

10. **Account snapshots.** EA reads native currency, login/server/company, mode, leverage, balance, equity, margin and free margin. JUVO reuses/creates a TradingAccount without resetting its original balance, notes, or journal history. Updates are durable initially, on transaction/reconnect and periodically; existing account realtime events update dashboard balances.

11. **History.** Native MT5 deals and historical orders upload in bounded pages. Each event is upserted by connection/kind/ticket. Batch receipts record acknowledged page numbers. Normalization occurs only after all pages arrive; successful reconciliation advances a durable server-time checkpoint. Missing entry data prevents checkpoint advancement and produces a visible warning instead of fabricated trades.

12. **Open positions.** Full account snapshots upsert shared BrokerPosition documents using stable position identifiers. Missing positions become closed snapshots, while realized journal records are created only from actual closing deals. Reconnect uploads a complete position snapshot even if no transaction event fired while offline.

13. **Realtime P/L.** Current price/native gross position profit update process memory and JUVO's existing user-scoped realtime channel. They do not trigger per-tick Mongo writes. SL/TP, volume, swap and structural changes are durable. Gross floating profit remains separate from net realized deal P/L and reporting-currency conversion.

14. **Transaction handler.** `OnTradeTransaction` sets dirty flags only. HTTP, history selection and reconciliation run in `OnTimer`, respecting uncertain transaction order and avoiding blocking network work in the handler.

15. **Manual trades.** Account-wide native positions/history enumeration captures manual desktop and mobile-origin activity that reaches the terminal; it does not filter to the attached chart or magic number.

16. **Other EAs.** The same account-wide reconciliation captures trades from other EAs. Magic numbers remain strings to preserve 64-bit precision; reason/comment metadata is retained. JUVO does not interact with those EAs or issue trade commands.

17. **Partial closes.** Each realized closing deal is normalized against full position inventory. Entry commissions/fees are allocated proportionally; scale-ins use weighted entry price. Remaining exposure stays open. Netting reversals split realized old exposure from newly opened opposite exposure. No planned RR, risk, strategy or behavioral answers are invented.

18. **Offline reconciliation.** Heartbeat expiry marks stale/offline. Terminal restart retains an account-scoped credential/checkpoint. History replays with a one-day overlap, plus a full position snapshot. Requests retry with bounded backoff. A Sync button request is delivered in the next heartbeat. Restarting JUVO also requests reconciliation because its live cache is empty.

19. **Deduplication.** Unique account binding, hashed token, event ticket and batch indexes protect ingestion. Canonical trade IDs use the TradingAccount ID plus closing deal ID, preserving identity on re-pairing. Repeated page uploads do not count as new pages. Trade upserts preserve journal notes/reflections. Interrupted batches replay from the unadvanced checkpoint.

20. **Storage/revocation.** EA stores its credential in the MT5 file sandbox, scoped by a hash of API origin/server/login. It is plaintext credential storage protected by the OS user profile, not a vault. Browser disconnect unsets the token hash, marks snapshots unknown and keeps trade history. EA `DisconnectAndClear` also removes its local state after server acknowledgement. Old tokens cannot authorize future uploads. A new pairing code is required to reconnect after revocation.

21. **Frontend.** Existing broker page now shows MT5 installation steps, downloadable EA, server address with copy control, expiring code generation/copy, masked account, currency, heartbeat/history times, connected/stale/offline state, sync request and disconnect. It does not display trade tables or collect broker passwords. Open positions and imported closed trades use existing dashboard/journal/analytics paths.

22. **Installation.** Download the source from Brokers, place it in MT5 data folder `MQL5/Experts`, open in MetaEditor, whitelist the JUVO server origin under Tools / Options / Expert Advisors, attach to a separate chart, and enter ApiUrl/PairingCode. Enable AllowLocalHttp only for loopback development. Keep MT5 running and online. Detailed steps and ten demo/offline acceptance scenarios are in the adjacent connector README.

23. **Compilation.** F7 in MetaEditor generates the EX5 beside the MQ5. The installed MetaEditor was used during verification, with zero errors and zero warnings. Compilation does not attach the EA to a chart or execute it against a broker account.

24. **Security.** HTTPS enforcement in production; explicit trusted proxy configuration; short-lived hashed pairing codes; scoped/revocable opaque tokens; owner checks; allowlisted bounded request schemas; string ticket IDs; rate limits; 512 KB connector body limit; fixed response protocol; no-store responses; hidden token/resource fields; safe development logs only. Browser JWT and connector token authentication are separate. Private state files must not be shared. In-flight uploads are serialized per connection in one backend process.

25. **Verification.** All 57 backend tests and 20 client tests passed, along with frontend lint and production build/TypeScript. Backend tests cover pairing expiry/retry, ownership/revocation, malformed data, replay receipts/checkpoints, price-only memory updates, heartbeat states, partial closes/reversals, fees, migration and cTrader shared mapping. Browser tests at 1440px and 390px verified pairing and sync with mocked API data, no horizontal overflow or page errors. Backend HTTP tests use mocked persistence and real local HTTP requests; these are not a live broker integration test. The final EA compile reported zero errors and zero warnings. The running backend returned HTTP 200 for health/download and 401 for unauthenticated connector status. The migration dry run returned zero remaining legacy connections, trades or positions.

26. **cTrader regression.** Its OAuth/controller routes, socket/client/manager and broker protocol files were left independent. Regression tests verify its shared schema constraints, position identity, native money and close/live P/L mappings, and the existing backend health endpoint responds. A fresh end-to-end OAuth and demo trade lifecycle was not performed; do that manually before claiming broker-live validation.

27. **Remaining MT5 limits.** Desktop must run; single backend process only; no historical broker-DST schedule; finite history/page/position limits; broker must expose the required entry deals. Separate balance charges are not arbitrarily assigned to trades. Historical broker deletions outside the overlap are not automatically reversed. Cross-server identical login/broker conflicts are safely rejected under the existing TradingAccount index until a dedicated account-index migration. No live demo-account acceptance test has been run. **External legacy MetaApi resources are not automatically undeployed by deleting this SDK: review that provider's console and stop/remove unused resources separately to avoid ongoing charges.**

28. **Future MT4.** Add a separate `JUVOConnector.mq4` and explicit platform negotiation/account hashing. MT4 uses orders rather than MT5 deals/positions and lacks the same OnTradeTransaction model; implement polling/diff reconciliation and platform-specific history normalization. Expand validation, account identity and fixtures without weakening MT5 or cTrader behavior. Do not merely enable an MT4 selector against this MT5-only protocol.
